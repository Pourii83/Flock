روشی را انتخاب کنید که به سرورتان می‌خورد:

| | روش ۱: داکر | روش ۲: اسکریپت آنلاین | روش ۳: اسکریپت آفلاین |
|---|---|---|---|
| **مناسب برای** | سرورهایی که داکر دارند | بیشتر سرورها (پیشنهادی) | سرورهای بدون اینترنت (پایدار) |
| **نیاز روی سرور** | Docker و Compose | اینترنت و دسترسی root | دسترسی root و PostgreSQL یا یک دیتابیس در دسترس |
| **نتیجه** | ۳ کانتینر (دیتابیس، API، وب) و HTTPS اختیاری | یک سرویس systemd به نام `flock` و PostgreSQL | مثل روش ۲ |
| **HTTPS** | داخلی (Caddy)، با `--profile https` | داخلی (Nginx و Let's Encrypt)، با `--domain` | مثل روش ۲، اگر سرور به Let's Encrypt دسترسی داشته باشد |
| **به‌روزرسانی** | `git pull` و `docker compose up -d --build` | اجرای دوباره‌ی اسکریپت | اجرای اسکریپتِ بسته‌ی جدید |

## پیش از شروع

این‌ها را لازم دارید:

1. **یک سرور لینوکس.** برای یک جمع دوستانه ۱ هسته‌ی پردازنده و ۱ گیگابایت رم کافی است. روش‌های ۲ و ۳ روی لینوکس ۶۴ بیتی (x64 یا arm64) با glibc 2.28 به بالا کار می‌کنند: Ubuntu 20.04+، Debian 10+، RHEL/Rocky/Alma 8+.
2. **یک دامنه** (پیشنهادی)، مثلاً `chat.example.com`، با **رکورد A** که به IP سرور اشاره کند. مرورگرها دوربین و میکروفون را فقط روی HTTPS اجازه می‌دهند، پس **تماس از وب‌اپ به HTTPS نیاز دارد** و HTTPS به دامنه.
3. **پورت‌های باز** در فایروال سرور و در پنل شرکت میزبان:

   | پورت | کاربرد |
   |---|---|
   | 80 و 443 (TCP) | وب‌اپ و API روی HTTP/HTTPS |
   | 4000 (TCP) | API بدون دامنه (روش ۲ و ۳، وقتی `--domain` نمی‌دهید) |
   | 8080 و 4000 (TCP) | وب‌اپ و API بدون دامنه (روش ۱، بدون پروفایل `https`) |
   | 3478 (UDP/TCP)، 5349 (TCP)، 49160 تا 49200 (UDP) | فقط اگر رله‌ی TURN نصب کنید ([چرا](/fa/calls/)) |
